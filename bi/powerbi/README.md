# Power BI: the Executive Summary dashboard

A six-page Power BI report on the same results as the Streamlit app: the answer-first executive summary,
a leakage and payment drill-down, the process, the business case, the monthly control report, and a
**Checks** page that compares every headline figure with the Python value.

Power BI Desktop runs on Windows only, so this folder holds everything needed to build the `.pbix` by
hand in about 90 minutes. Each step gives the number you should see. If a number differs, stop and fix it
before you go on.

| File | What it is | Used in step |
|---|---|---|
| [`queries/*.pq`](queries/) | One Power Query (M) script per CSV, with every column's type set using the en-US locale. Generated by `scripts/export_bi_data.py` | 1 |
| [`date_table.dax`](date_table.dax) | The Date table (DAX calculated table) | 2 |
| [`measures.dax`](measures.dax) | All 40 measures as one DAX query, plus two result tables to check them | 4 |
| [`theme.json`](theme.json) | Report theme in the app's colours | 5 |

**The rule that matters:** Power BI only adds up, counts and divides. Every flag, cause and € of leakage
was computed in Python and exported to `bi/data/`, so no detection rule (duplicate pairs, the 115% budget
threshold) is rebuilt in DAX, and the report can't disagree with the app. `tests/test_powerbi.py` mirrors
each measure in pandas and checks that it reproduces the Python figures, so the definitions are checked
before you build anything.

---

## 0. Before you start (5 minutes)

1. Install **Power BI Desktop** (free, from the Microsoft Store). You need a version from 2024 or later,
   because step 4 uses *DAX query view*.
2. Copy the repo's `bi` folder to the PC, for example to `C:\ap-spend-leakage-analyzer\bi\`.
3. Open Power BI Desktop with a blank report. **File → Options and settings → Options**:
   - *Current file → Data Load*: untick **Auto date/time** (the report has its own Date table) and, under
     Relationships, untick **Autodetect new relationships after data is loaded** (step 3 sets them by hand).
4. Save the empty report as `bi\powerbi\AP_Spend_Leakage.pbix`.

## 1. Load the data with the Power Query scripts (20 minutes)

The scripts do what a manual CSV import gets wrong on a German-locale PC: they read `2122.75` as
2,122.75 (not 212,275) and `2026-01-19` as a date, for every column, without a *Using Locale* step.

1. **Home → Transform data**. The Power Query editor opens.
2. **Home → New Source → Blank Query**, then **Home → Advanced Editor**. Paste the whole of
   `queries/DataFolder.pq`. Change the path to your `bi\data\` folder, **keeping the backslash at the end**.
   Click Done, then rename the query (right-click → Rename) to **`DataFolder`**. It shows as a parameter.
3. Repeat for each table below: **New Source → Blank Query → Advanced Editor**, paste the script,
   Done, rename the query to the script's file name. The names must match exactly: the DAX uses them.

   | Query | Rows | Query | Rows |
   |---|---|---|---|
   | `Invoices` | 2,550 | `LeakageByCause` | 4 |
   | `Vendors` | 40 | `BusinessCaseScenarios` | 3 |
   | `InvoiceEvents` | 10,882 | `BusinessCaseTornado` | 10 |
   | `LeakageByInvoice` | 457 | `ImpactEffortMatrix` | 6 |
   | `LeakageByDriver` | 6 | `ControlReport` | 132 |
   | `HeadlineFigures` | 18 | | |

   The other three scripts (`Budgets`, `BusinessCaseLevers`, `CtqBaseline`) aren't used by the report. Load
   them only if you want to explore.
4. **Check before you close:** in `Invoices`, the first row's `amount` is **2,122.75** (or 2.122,75 in German
   display) and `discount_taken` shows TRUE, FALSE or *null*. The column icons show *1.2* for amounts, a
   calendar for dates and a check mark for `has_po`.
5. **Home → Close & Apply**.

## 2. Add the Date table (5 minutes)

1. **Modeling → New table**, paste `date_table.dax` and press Enter. It has **396 rows** (1 Aug 2025 to
   31 Aug 2026).
2. **Table tools → Mark as date table**, column `Date`.
3. Select the column `Month label`: **Column tools → Sort by column → Month start**. Without this,
   months sort alphabetically (Apr, Aug, Dec…).

## 3. Set the relationships (10 minutes)

Open **Model view**. Drag each column onto the other, or use **Home → Manage relationships → New**.
All of them are one-to-many with single cross-filter direction.

| From (one side) | To (many side) | Active | Why |
|---|---|---|---|
| `Vendors[vendor_id]` | `Invoices[vendor_id]` | Yes | Supplier names, terms and net days |
| `Date[Date]` | `Invoices[invoice_date]` | Yes | Spend, PO compliance and leakage count in the month the invoice came in |
| `Date[Date]` | `Invoices[paid_date]` | **No** (untick *Make this relationship active*) | Payment measures switch to it with `USERELATIONSHIP`, so they count in the month of payment |
| `Invoices[invoice_id]` | `LeakageByInvoice[invoice_id]` | Yes | Hard leakage follows the department, vendor and month slicers |
| `Invoices[invoice_id]` | `InvoiceEvents[invoice_id]` | Yes | Rejections by reason |

The remaining tables (`LeakageByDriver`, `LeakageByCause`, `BusinessCase*`, `ImpactEffortMatrix`,
`ControlReport`, `HeadlineFigures`) stay unconnected: they are already summarised by Python.

Why two date relationships: the monthly control report (`src/control.py`) puts payments in the month
they were paid and entries in the month they came in. The report does the same, so its monthly figures
match the Control tab.

## 4. Add the measures in one go (15 minutes)

1. **Home → Enter data**. Name the table **`_Measures`**, leave the one empty column, click **Load**.
2. Open **DAX query view** (the fourth icon on the left). Paste the whole of `measures.dax` and click
   **Run**.
3. Click **Update model with changes** (top of the editor). Every measure is added to `_Measures`.
4. Check the two result tables under the editor:
   - The first row shows **Total spend 3699592**, **Hard leakage 73552.87…**, **DPO 11.4…**
     and **Checks: ALL OK**.
   - The second table lists the 18 headline figures. Every row says **OK**, except
     `expected_duplicate_recovery_eur`, which says **From Python**: it is an assumption times a count,
     passed through, so there is nothing to recompute.
5. In the Data pane, delete `Column1` from `_Measures`. The table moves to the top with a calculator icon.
6. Set the formats in **Model view**: Ctrl+click several measures, then in **Properties → Formatting**:

   | Format | Measures |
   |---|---|
   | Custom `€#,0` | Total spend, Hard leakage, Spend at risk, No-PO spend, Expected duplicate recovery, Investment, Annual hard benefit, NPV, hard benefits, NPV with estimated savings, NPV change (worst and best value), NPV swing |
   | Percentage, 1 decimal | Hard leakage % of spend, On-time payment %, Discount capture %, PO compliance %, Rework %, Rework % of paid invoices, ROI, hard benefits |
   | Percentage, 0 decimals | Duplicate share of hard leakage, Cumulative share |
   | Decimal number, 1 decimal | Days payable outstanding, Agreed payment days, Median days, submission to payment, Payback months |
   | Whole number | Invoice count, Paid invoices, Invoices with hard leakage, Discount invoices paid, Discounts taken, Rejections, CTQs on target, CTQs reported |

## 5. Apply the theme (1 minute)

**View → Themes → Browse for themes** → `theme.json`. The bars turn the app's blue, orange and green.

## If something looks wrong

| Symptom | Cause and fix |
|---|---|
| Amounts 100 times too large, or dates missing | The CSV was loaded with *Get Data → Text/CSV* instead of the script. Delete the query and paste the script |
| *Expression.Error: … DataFolder …* | The parameter is missing, misnamed or has no backslash at the end (step 1.2) |
| *Cannot find table '_Measures'* when running the DAX | Create the `_Measures` table first (step 4.1) |
| Payment measures blank, or identical every month | The `paid_date` relationship is missing. It must exist, and be **inactive** (step 3) |
| Months sort Apr, Aug, Dec… | `Month label` isn't sorted by `Month start` (step 2.3) |
| No *Update model with changes* button | Power BI Desktop is older than 2024. Update it, or add each measure with **Modeling → New measure**, pasting the text after `MEASURE '_Measures'` |
| Checks page shows CHECK on a row | A column type is wrong (usually an amount read as text). Look at that table's icons in Power Query |

## Design choices worth explaining in an interview

- **Star schema.** `Invoices` is the fact table; `Vendors` and `Date` filter it; leakage and events hang
  off it by `invoice_id`. Summary tables from Python stay unconnected on purpose.
- **Two date relationships, one inactive.** Payments count in the month paid, entries in the month
  received, the same convention as the Python control report. That is why the monthly figures agree.
- **No rule rebuilt in DAX.** One definition of a duplicate or a budget overrun, in Python, tested
  against the planted answer key. Power BI aggregates and presents.
- **No budget-vs-actual chart.** Summed to department level, every department looks about 60% under
  budget, because the overruns sit in single department-category-months. That chart would tell a CFO
  the opposite of the truth, so overruns appear as spend at risk and in the control report instead.
- **A Checks page inside the report.** The same idea as the Excel model's Checks sheet: the report
  proves its own numbers against the source before anyone relies on it.
